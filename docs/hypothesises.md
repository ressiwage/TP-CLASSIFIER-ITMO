# гипотезы
В этом разделе -- сделанные мной гипотезы на основе задания и аксиом. Если гипотеза следует из другой гипотезы, в скобках -- номер этой гипотезы в формате Г0 либо аксиомы А0.
## гипотеза №1
Если перед нами встаёт задача оптимизировать ВСЕ обращения (что невозможно априори), то нам необходима тяжёлая LLM модель для этого, вроде QWEN-3.8-MAX.

это основывается на том, что мелкие нейросети часто галлюцинируют и плохо выполняют инструкции.

## гипотеза №2
Для оптимизации типовых обращений не обязательно брать тяжелую модель, достаточно выполнить поиск по базе

## гипотеза №3(Г1)
гипотеза 1, возможно, нецелесообразна, учитывая дороговизну тяжелых нейросетей как через АПИ, так и self-hosted.

## гипотеза №4

значимый ответ оператора техподдержки как правило не занимает много символов, значит если эту функцию переложить на LLM то токены будут стоить дёшево.

## гипотеза №5

Среднее арифметическое по выходным токенам (плюс амортизация ~40%) для нетривиальных тикетов -- 1000, для тривиальных -- 400. Вывод сделан из тестового датасета, сгенерированного Deepseek Expert, см. AI_USAGE.md

## гипотеза №6(А4)

Входные токены дешевле Выходных в 5 раз, и запросы часто будут короче чем ответы. следовательно, можно рассчитать цену входных токенов как 1/10 выходных.

## гипотеза №7

RAG будет стоить приблизительно 2000 токенов к запросу: 3 простых выходных запроса + амортизация 40%. 

## гипотеза №8(Г2)

для тривиальных запросов мы можем взять классификатор и векторный поиск, что будет сильно дешевле чем любая БЯМ.

## гипотеза №9(Г6,Г5,Г4,А4)

цена ответа для Claude Sonnet 5:
RAG: (2000/1e6)*2.5=0.05$
тривиальный вопрос: 0.05+(400/1e6)*(25+2.5)=0.061$=4.88р
нетривиальный вопрос: 0.05+(1000/1e6)*(25+2.5)=0.0875$=7р

## гипотеза №10
